Deciding what the agent does on its own

Autonomy levels

The most important design decision was not the screens. It was deciding, for every action, whether the agent acts, suggests, or hands over. The rule: the more money or commitment involved, the more control stays with the user.

ActionLevelWhy
Understand needs and usageAgent actsLow risk. Asks one question at a time and only when it is unsure.
Check address and coverageAgent suggests, user confirmsA wrong address breaks everything after it, so the detected address is always confirmed.
Recommend a planAgent suggests, user confirmsAlways explains why, and shows two alternatives so the choice stays with the user.
Apply offers and discountsAgent actsOnly saves money. Conditions like Auto Pay are shown in plain words.
Add TV, phone or extrasAgent suggests, user confirmsNever pre-selected. This was a key problem in the old flow.
Place the order and payUser approvesThe agent prepares everything, the user gives the final yes.
Failed payment, cancellations, complaintsHand to a personHanded off with full context, so the user never repeats themselves.

Testing the design

Design evals

An agent can say anything, so “looks good in Figma” is not enough. I wrote the rules the agent must always follow as test cases, and ran every scenario against them. Each one passes only when a scenario proves it.
